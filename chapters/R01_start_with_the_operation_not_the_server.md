# R01 — Start with the operation, not the server

[Project overview](/README.md) · [Company profile](/company_profile.md) · [Chapter index](/chapters/README.md)

**Fictional case analysis.** People, events, quantities and records are invented. Framework propositions are attributed separately; the analysis is not a real-company compliance conclusion.

### Framework context

OSFI E-21 addresses critical operations, dependency mapping, tolerances for disruption and scenario testing. The test methods in this case are illustrative. [S03](https://www.osfi-bsif.gc.ca/en/guidance/guidance-library/operational-risk-management-resilience-guideline)

### The scene

Omar begins the meeting with a list of critical servers. Every system has a recovery owner. Leena asks whether the list tells her which customers will receive urgent claims support during a disruption.

Nobody can answer from the server list alone.

Cedarline's claims process spans initial notification, customer verification, claim recording, triage, adjuster assignment, payment authorization and communication. Different claims have different urgency. The study focuses first on the ability to receive and triage urgent claims, rather than declaring the entire insurer equally critical.


### Work the decision

Ana asks Leena to define the delivered outcome and the boundaries: who needs the service, which steps are necessary, which channels count, and where the operation starts and ends. The team must then decide whether this operation is critical using the institution's approved criteria and the reasons recorded.

A process can be commercially important without meeting that criticality definition. A shared technology can support several critical operations without itself being the right unit for the business-impact conclusion. The labels should support a decision, not award prestige to departments.

For this exercise, urgent-claim intake and triage is a **candidate** critical operation. Leadership has not yet confirmed the classification. Ana records that uncertainty rather than quietly turning a workshop suggestion into an approved inventory item.
